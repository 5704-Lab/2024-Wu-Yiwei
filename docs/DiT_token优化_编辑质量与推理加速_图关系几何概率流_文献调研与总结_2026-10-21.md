## 0. 研究目标、证据范围与主要结论

### 0.1 本次真正要回答的问题

研究对象不限于“剪掉不重要 token”。凡是明确改变 token 的选择、表示、位置、交互、计算频率、传播、参考注入或精度，并以生成／编辑质量或计算效率为目标的方法，都属于检索范围。用户补充的“重要 token 作为锚点”单列为主线。

具体问题是：

1. 已有工作用什么观测定义 token 的相关性、重要性和代表性？选择的是图像、文字、源图条件、视频帧，还是额外学习的 token？
2. token 被用作合并目的节点、稀疏计算节点、动力学代理、条件参考，还是身份／结构的语义载体？
3. 改变预训练模型时，实际改变什么，是否需要训练、校准、反演、额外模型、参考图或内部编辑区域？
4. 哪些证据涉及真实编辑中的无关区域变化、姿态、视角和身份，哪些仅证明生成分布质量或对原始模型输出的近似？
5. 从图论、黎曼几何和概率流解释这些方法时，哪些结论成立，哪些只是直觉？

**覆盖目标是机制完整，而非宣称检索穷尽。** 正文建立可追溯的方法清单，覆盖代表性原始论文及截至检索日核验到的近期工作；不能把“所有利用 token 的论文”视为已获证明的全集。纯粹改变步长、整模型量化、蒸馏或提示词改写，而没有明确 token 机制的工作，不逐篇扩展。训练效率工作作为边界支线纳入，避免与推理速度混淆。

表格共列 **82 个方法／家族条目**：34 个效率条目、27 个编辑／个性化条目、21 个表征／引导／训练关系条目；包含少量明确标注的邻近前作，家族和不同版本不等于独立论文数。锚点重点读第 2 节，方法全表见第 3—5 节，图与几何辨析见第 6—10 节，保证边界见第 11—12 节。

### 0.2 与现有项目约束的关系

广泛纳入相关工作，不等于放宽当前项目的使用条件。涉及已有 FlowEdit 主线时，仍分别检查：冻结预训练模型、无新训练／微调、无额外 LLM 对齐、无额外参考图、无空间／注意力编辑区域掩码，以及是否支持免反演。源图本身不等于“额外参考图”。

“无需用户画 mask”不能替换“内部不构造 mask”。计算选择索引也不必然是编辑区域：ToCa 的缓存索引主要决定哪里重新计算，ColorCtrl 的区域图则决定哪里保留颜色。两者都可能是二值张量，但语义与干预作用不同。

### 0.3 先给出结论

**第一，重要性至少有四种，不能合成一个未经验证的概念。**

- **计算重要性**：不重新计算这个 token，会使原模型输出误差增加多少？
- **条件重要性**：它在当前文字／参考条件的信息传递中起多大作用？
- **保持重要性**：它承载源实例哪些必须保留的细节、姿态和视角？
- **代表性**：选中它之后，其他 token 是否得到充分覆盖，能否从它近似恢复？

ToCa、Importance-Based Token Merging、ToMA、ResCa、JiT 分别给出了不同答案。DuCa 的选择消融进一步表明，在其设置中随机／多样化刷新可以优于某些“高重要性”排序；这不是对所有重要性方法的否定，却足以反对通用重要性分数的假设。[ToCa](https://arxiv.org/abs/2410.05317)、[重要性合并](https://arxiv.org/abs/2411.16720)、[ToMA](https://arxiv.org/abs/2509.10918)、[DuCa](https://arxiv.org/abs/2412.18911)。

**第二，锚点是运算角色，不自带语义保证。** 合并锚点代表特征，ResCa 的代理代表短期残差，JiT 的锚点代表稀疏速度计算；它们没有因此成为能保证“同一只猫”“车辆仍为原视角”的身份锚点。[ResCa](https://fanghaipeng.github.io/ResCa/)、[JiT](https://arxiv.org/abs/2603.10744)。

**第三，最接近“提高编辑质量同时减少无关区域计算”的直接证据，来自编辑专用方法。** SpotEdit、CacheEdit、KV-Edit 的相关性明显高于普通文生图加速；但它们依赖内部区域划分、源条件流或特定编辑骨干。不能把其结果直接写成严格无掩码 FlowEdit 的已解决方案。[SpotEdit](https://arxiv.org/abs/2512.22323)、[CacheEdit](https://proceedings.mlr.press/v306/yu26e.html)、[KV-Edit](https://arxiv.org/abs/2502.17363)。

**第四，图的“保留相似性”与“表达语义关系”是两个层次。** 单帧余弦图、标量注意力图和 Gram 图都存在不可辨认的变化；位置、有向关系、部件对应和时间信息各自增加表达能力，也各自带来错误匹配或过度冻结风险。已有证据支持讨论这些必要性质，尚不足以断言某一种图已经同时解决姿态、视角、身份和任务兼容保持。

### 0.4 如何阅读证据

全文中的“作者报告”指论文自己的实验，并非本项目复现。表格标记：

| 标记 | 含义 |
|---|---|
| 冻结 | 该操作不更新骨干权重；不自动表示整个系统无需训练 |
| 校准 | 有离线统计、敏感度分析或超参数选择；与权重学习分开 |
| 训练 | 新模块、LoRA、蒸馏或结构适配需要学习 |
| 直接编辑 | 原文包含编辑任务证据 |
| 生成证据 | 原文主要证明生成速度／质量，不能直接外推实例保持 |
| 邻近前作 | 机制相关，但不是原生 DiT 证据 |

近期预印本按核验版本理解。一个 arXiv 编号可能对应后来改题或扩展的版本；例如 DuCa 和 AnchorCache 的早期／后期描述不同，不能拼成一套未经核验的方法。论文中的“near-lossless”均是指定指标和预算下的经验说法。

## 1. token 优化的完整分类

### 1.1 五种 token，五种不同的问题

令图像状态的 patch token 为 $X$，文字 token 为 $T$，源图／参考条件 token 为 $C$，额外寄存 token 为 $R$；视频还增加帧坐标。

| token 对象 | 常见优化 | 为什么不能混同 |
|---|---|---|
| 待生成／待编辑的 $X$ | 合并、缓存、剪枝、速度插值、局部重算 | 它们是需要最终恢复的输出状态 |
| 清晰源图／参考 $C$ | 保留、压缩、KV 复用、选择性注入 | 提供上下文，不一定需要自身去噪 |
| 文字 $T$ | 条件加权、属性绑定、模板 token 分析 | 相关性可能表示指令、格式或寄存功能 |
| 学习／复制的 $R$ | 全局信息聚合、弱模型引导 | 新增 token 是否有效取决于训练和支持结构 |
| 帧／部件／区域 token | 对应传播、轨迹控制、区域汇聚 | 存在跨位置、跨时间和可见性问题 |

FLUX-Kontext、Qwen-Image-Edit 中已有清晰源图条件通道，并不意味着原始 SD3／FLUX 文生图模型无需适配就能任意拼接源图 token。OminiControl 等方法专门通过训练建立这条接口。

### 1.2 按运算分解

从图论看，可以把文献分为以下既有机制。这里是对方法的重述，不声称每篇作者都显式使用了图论。

| 运算 | 图论解释 | 代表方法 |
|---|---|---|
| 相似性合并 | 二部匹配、节点聚合与粗化 | ToMeSD、重要性合并、ToMA、DaTMe |
| 稀疏 token 计算 | 选代表节点、保留／近似其余节点状态 | RAS、CAT、JiT |
| 缓存／预测 | 沿采样时间增加复用边／预测边 | ToCa、DuCa、TaylorSeer |
| 代理传播 | 簇内从代理节点传播动力学信息 | ResCa |
| 稀疏注意力 | 删除边／块，通常保留输出节点 | SVG、SVG2、STA、SpargeAttention |
| 编辑特征注入 | 源—目标的跨分支边及边权重修改 | KV-Edit、FreeFlux、ReFlex、HeadRouter |
| 位置／对应控制 | 修改节点坐标、匹配边、相对位置关系 | QK-Edit、LazyDrag、ContextDrag、FiT |
| 条件 token 压缩 | 条件—目标二部信息流压缩 | ToPi、OminiControl2、AnchorCache |
| token 表征干预 | 修改节点特征或制造弱预测分支 | DiTF、EMA、TPG、STAS、寄存器引导 |
| token 精度分配 | 对节点表示误差设不同预算 | ViDiT-Q、Q-VDiT、S²Q-VDiT |
| 训练时关系学习 | 学习缺失节点恢复或对齐特征关系 | MaskDiT、MDT、REPA、iREPA |

### 1.3 质量和速度各有多个含义

需要分别识别：①生成分布质量，②提示词符合度，③对未加速输出的保真度，④真实源实例保持，⑤编辑任务完成，⑥多轮／跨帧一致性。

同样，FLOPs 下降、注意力核速度、DiT 模块耗时、端到端延迟和显存不是同一指标。减少 token 后，排序、匹配、gather/scatter、RoPE 重排与缓存访存可能成为瓶颈。原本调用一次的骨干若改为“正常预测＋扰动预测”，质量可能提高但推理更慢。不能把“优化质量”默认表述为“加速”。

## 2. 重要 token 与锚点：本轮重点

### 2.1 先区分八种“锚”

| 锚的含义 | 已有工作 | 实际保证／经验用途 | 未被保证的内容 |
|---|---|---|---|
| 合并目的 token | Importance-Based Token Merging | 让后续计算集中于重要特征代表 | 不保证该 token 的源身份语义 |
| 覆盖代表 token | ToMA | 优化代表集合的特征覆盖 | 不保证姿态和实例保持最优 |
| 不参与合并的结构 token | DaTMe | 避免重要轮廓被平均 | 不区分轮廓变化是否为必要编辑 |
| 稀疏速度锚 | JiT | 用少量 token 驱动全状态近似速度 | 不保证与完整注意力场相同 |
| 簇内动力学代理 | ResCa | 同簇残差传播，减少真实重算 | 不保证跨语义边界仍有相同动力学 |
| 条件贡献代表 | ToPi | 保护对目标有贡献的参考 token | 不保证被剪条件对身份无用 |
| 静态文字锚 | AnchorCache | 使参考分支有指令信息且可缓存 | 不是由重要性排序得到的源物体锚 |
| 源实例／对应参考 | Personalize Anything、LazyDrag 等 | 在参考或交互约束下保持主体／对应 | 不能取消参考、mask、反演等前提 |

这张表直接回答用户补充：**“以重要 token 为锚点”确实是一条独立文献线，但必须同时调查选择准则、覆盖、传播对象和锚点失效条件。**

### 2.2 Importance-Based Token Merging：最直接的“重要性→锚点”

原文早期题名为 Importance-based Token Merging for Diffusion Models，正式论文题名为 Importance-Based Token Merging for Efficient Image and Video Generation。其关键不只是“相似 token 合并”，而是先决定哪些 token 可以成为合并后的计算代表。[论文](https://arxiv.org/abs/2411.16720)、[ICCV 正文](https://openaccess.thecvf.com/content/ICCV2025/papers/Wu_Importance-Based_Token_Merging_for_Efficient_Image_and_Video_Generation_ICCV_2025_paper.pdf)。

作者使用条件与无条件预测之差的幅度：

$$
I_i^{\mathrm{CFG}}
=\left\|\epsilon_\theta(x_t,t,c)_i
-\epsilon_\theta(x_t,t,\varnothing)_i\right\|.
$$

其含义接近条件显著性：哪些位置对加入该条件最敏感。先构造重要 token 池，再从池中随机选目的 token，保留与目的 token 不相似的独立重要 token；其余 token 向目的 token 合并。重要性和多样性同时起作用，并非直接取前 $k$ 个。

**图论解释**：重要节点候选集上的代表选择，随后建立源—目的二部合并关系。重要节点成为后续信息计算的承载者。

**证据边界**：论文包含 PixArt 等 Transformer，以及 U-Net／多视角／视频应用，不能把全部实验都算作 DiT。它改善的是压缩后生成质量；在不完整描述编辑中，未被文字提及的源纹理可能具有低 CFG 分数却有高保持价值。内嵌引导模型也未必提供条件／无条件两次预测，“CFG 信号免费”只适用于本来已计算两个分支的配置。

### 2.3 ToMA：代表性是集合性质

ToMA 将目的 token 选择写成 facility-location 覆盖目标：

$$
F(D)=\sum_{i\in V}\max_{j\in D}S_{ij},
$$

其中 $S$ 是 token 特征相似性，$D$ 是保留的代表集合。它倾向于选出能覆盖不同特征簇的代表，而非把预算集中在同一前景的多个相近 token。合并／展开通过矩阵运算实现，并利用局部窗口和映射复用降低开销。[论文](https://arxiv.org/abs/2509.10918)、[ICML 正文](https://raw.githubusercontent.com/mlresearch/v267/main/assets/lu25v/lu25v.pdf)。

**理论边界**：标准归一化、单调次模、基数约束条件下，贪心的近似保证约束的是上述集合目标。它不直接约束最终图像误差，更不是身份／视角保证。直接使用可能为负的余弦相似性时，也要检查目标的基线与非负化约定。

**数值边界**：设合并矩阵为 $M\in\mathbb R^{m\times N}$，一般 $m<N$。即使展开用 $M^\top$ 或伪逆，仍不能精确恢复所有原始 token。论文将转置展开作为高效近似，不能把“近似正交”写成无损重建定理。ToMA 对 FLUX 的位置编码处理也说明：特征相似不能替代位置一致性。

### 2.4 DaTMe：时间上安静，不等于结构上可丢

Which Tokens to Merge? Diffusion Dynamics for Efficient Image Generation，方法名 DaTMe，是本轮核验到的 2026 年 10 月近期预印本。它直接讨论 CFG 重要性偏向提示词前景、遗漏背景细节的问题。[论文](https://arxiv.org/abs/2610.22370)。

其两个主要观测为：

$$
M_{\mathrm{temp}}^{(t)}
=|\hat x_0^{(t)}-\hat x_0^{(t-1)}|,
\qquad
M_{\mathrm{spat}}^{(t)}
=|\hat x_0^{(t)}-\operatorname{Up}(\operatorname{Down}(\hat x_0^{(t)}))|.
$$

前者描述清晰预测的变化，后者描述轮廓和局部细节。方法综合排序：相对稳定且低结构响应的 token 优先进入合并源集合；部分高时间／高结构响应 token 不参与合并，成为结构锚；补足预算时考虑空间分布，匹配限制在空间邻近目的 token。

**对本项目的价值**：它提供“未被文本关注的区域仍可能含重要结构”的直接加速文献证据，比把低 CFG 简单称作背景更可靠。

**限制**：它仍主要研究生成时压缩质量；预测很快稳定下来也可能是过早收敛到错误视角。文中的时间差公式依赖具体采样更新及索引约定，不能无条件推广到任意 Flow Matching 求解器。其伪真值是同一模型最终生成的结果，不是源实例应保持的真实语义。近期结果尚不能替代跨方法独立验证。

### 2.5 ResCa：锚点传播的是多阶残差

ResCa 不直接用簇中心替代所有 token 状态，而是在历史去噪轨迹上聚类，在稀疏步仅对每簇一个代理 token 做真实计算，用代理的多阶残差驱动其他 token 的模拟更新；稠密步重新获取历史和簇信息。[作者项目](https://fanghaipeng.github.io/ResCa/)、[CVPR 正文](https://openaccess.thecvf.com/content/CVPR2026/papers/Fang_ResCa_Residual_Caching_for_Diffusion_Transformers_Acceleration_CVPR_2026_paper.pdf)。

它针对两种失真：缓存容易过时，合并容易沿别的 token 的方向更新。代理残差的目的，是保留每个 token 自身状态，同时借用相似动力学的变化量。

**图论解释**：历史轨迹相近的节点构成簇，代理节点向簇成员传播残差信息。锚点选择依据是动力学代表性。

**限制**：短期轨迹相近并不推出未来所有时间仍相近；编辑改变条件后，原簇中的两个部件可以分化。作者页面的最高 5.5 倍明确涉及 GFLOPs，不能原样写成端到端延迟收益。论文主要是生成加速证据。

### 2.6 JiT：动态锚点与空间近似 ODE

Just-in-Time: Training-Free Spatial Acceleration for Diffusion Transformers，在 FLUX.1-dev 上使用逐渐增大的活动 token 集。将选择算子记为 $S_k$，其已有方法可写成：

$$
\dot y
=\Pi_k\,u_\theta(S_k^\top y,t),
$$

其中 $\Pi_k$ 把稀疏计算的速度放回锚点并插值到其余位置。新增 token 的选择用局部速度方差，阶段转换用 deterministic micro-flow 调整新 token 状态。[论文](https://arxiv.org/abs/2603.10744)。

这是与用户“重要性锚点＋概率流”最直接相关的工作：重要性不是静态注意力，而是局部速度变化；锚点预算随采样阶段增加。

**必须保留的数学区别**：

$$
S_k^\top\Pi_k u=u
\quad\not\Rightarrow\quad
u_\theta(S_k^\top y,t)=S_k^\top u_\theta(y,t).
$$

左式只说明插值不会覆盖已计算的锚点速度。右式涉及“删掉其他 token 后的网络”和“完整注意力网络”的一致性，一般不成立。因此所谓锚点上的精确性是相对于缩减输入的计算，并非相对于完整 DiT 的零误差。

同理，新增 token 匹配某一噪声尺度，不自动证明它们具有完整模型要求的联合相关性。微流命中构造目标，是有限时间状态转移性质；真实生成分布的精确一致还需要预测／插值及联合分布假设。原文的生成实验值得参考，但没有证明编辑身份、姿态或无关区域保持。

### 2.7 为什么不能只保留最高分 token

ToCa 的主要方向是避免重要 token 长时间不更新；DuCa 的消融则在给定刷新预算下发现，多样化／随机刷新可以优于一些注意力或范数排序。这两点并不矛盾：**避免刷新错误的节点**与**让刷新集合覆盖足够多的状态**同时影响结果。[DuCa](https://arxiv.org/abs/2412.18911)。

从现有文献可归纳出三项不同要求：单节点贡献、代表集合覆盖、更新的时间新鲜度。重要性合并的随机目的节点、ToMA 的次模覆盖、ToCa 的缓存年龄、RAS 的长期跳过补偿，都说明已有方法已超出“最高分就是全部答案”。

### 3.3 ToCa、DuCa、TokenCache 的重要差别

**ToCa** 的缓存分数综合四类因素：其他 token 对本 token 的读取影响、图像 token 的文字交叉注意力熵、距上次真实计算后的缓存次数，以及空间分布。分数高者优先重算。空间项旨在防止误差集中于某片区域，年龄项旨在防止长期过时；因此它本来就不是纯注意力中心性方法。[全文 §3.5](https://arxiv.org/html/2410.05317)。

按 $O_i=\sum_jA_{ij}V_j$ 的约定，$\sum_iA_{ij}$ 描述键／值节点 $j$ 被多少查询读取，不是行和；完整 softmax 的每一行和恒为一。文字熵衡量控制信息分布的广度，也不是某个目标编辑词的重要性。

**DuCa** 的核验全文包含“激进缓存＋保守缓存”，以及不同刷新选择的消融。它指出注意力分数提取与不显式物化注意力矩阵的高效核存在工程冲突；在给定 FLUX 刷新预算下，多样化选择优于高度相似的集中选择，随机选择也很有竞争力。不能据此推导“所有 token 同等重要”，较准确的结论是“刷新集合的覆盖与成本可以比某个排序代理更重要”。[全文 §IV-B](https://arxiv.org/html/2412.18911)。

**TokenCache** 则学习输入／时间条件的 Cache Predictor，并通过输出一致性与计算预算损失训练。核验版本还在末层使用 LoRA 并进一步适配。因此，虽然算法中的教师骨干可以冻结，它仍不满足当前项目的“无新训练／微调”约束。[全文 §III-C、IV-B](https://arxiv.org/html/2409.18523)。

### 3.4 RAS、CAT、SODA：重要性是动态风险，而非编辑标签

RAS 根据预测噪声统计与跳过历史选下一步活动 token；活动 token 的查询仍可读取未活动 token 的缓存 K/V，保留全局上下文。它比“只对活动子集做自注意力”更谨慎，但缓存内容仍有误差。[RAS](https://arxiv.org/html/2502.10389)。

**一个常见误解需要排除**：若某 token 的当前速度／噪声复用上一时刻预测，积分器仍在更新该位置的潜状态。跳过网络计算不等于像素或 latent 不变。只有显式固定／回填的编辑方法才具有另一层保持作用。

CAT 用相对历史噪声变化、选择频率和聚簇改善 token 选择的空间覆盖。SODA 则先对时间、层、模块及缓存／剪枝配置做敏感度分析，再分配计算。这些方法的“敏感”主要是对近似计算误差敏感；源实例未被文字描述的部件，不一定在该误差指标下得到优先保护。[CAT](https://arxiv.org/html/2502.00433)、[SODA](https://arxiv.org/html/2603.07057)。

### 3.5 ToPi：上下文 token 与目标 token 的角色不对称

ToPi 为上下文生成设计，先校准代表注意力层，再用目标查询对参考 token 的注意力与参考 V 范数估计贡献：

$$
I_j=\sum_{\ell,h}\|V_j^{\ell,h}\|_2
\sum_{i\in\mathrm{target}}A_{ij}^{\ell,h}.
$$

贡献较小的参考 token 被剪，选择随采样过程更新，并进行位置／上下文对齐。其优势是明确区分“被生成的状态”和“提供信息的条件”，比均匀压缩所有 token 更符合条件编辑结构。[ToPi](https://arxiv.org/html/2602.01609)。

两项边界尤其重要。第一，$A_{ij}\|V_j\|$ 是局部信号幅度代理，忽略不同值向量的抵消以及后续网络方向敏感性。第二，代表层应比较**联合注意力下参考子块所获质量**；若只在参考键集合内单独 softmax 再对全部键求和，行和恒为一，分数会退化。原文 §4.1 的局部记号需要结合联合注意力／实际实现理解，不能照抄后宣称任意层都可由该和区分。

### 3.6 训练改变了 token 接口时，速度收益不能直接迁移

HiLo-Token 同时保留低频全局 token、高频细节和膨胀 mask 内 token。其遮挡案例很有启发性：被遮物的对称纹理未必能靠当前匹配相关性发现，因此作者采用 Sobel 频率选取部分外部上下文。但完整流程明确包含 SFT 和少步蒸馏。[全文 §2.3—2.4](https://arxiv.org/html/2606.13898)。

DDiT 的动态调度依据 latent 的演化，支持不同 patch 大小则靠新增／适配 patch 接口及 LoRA 蒸馏。Elastic Token Compression 使用连通区域而非散乱相似性组，同样需要区域 token 接口微调。这些结果说明 token 几何确有价值，也说明改变分词／区域表示往往需要适配预训练分布。[DDiT](https://arxiv.org/html/2602.16968)、[Elastic Token Compression](https://arxiv.org/abs/2608.29281)。

### 4.2 Q、K、V 对应不同干预层次

对一个注意力头：

$$
A=\operatorname{softmax}(QK^\top/\sqrt d),\qquad O=AV.
$$

Q/K 修改“读谁”，V 修改“读到什么”。但这只是当前层算子分解，不是语义上的纯结构／纯外观分解。前层的文字交互与 AdaLN 已改变 Q/K/V，位置编码又影响 Q/K。QK-Edit、FreeFlux、ColorCtrl 的价值，在于通过实验识别某些有用控制位置，而不是证明所有层共享同一解耦。[QK-Edit](https://arxiv.org/html/2610.17829)、[FreeFlux](https://arxiv.org/html/2503.16153)、[ColorCtrl](https://arxiv.org/html/2508.09131)。

在图像查询在前、文字查询在后的约定下：

$$
A=
\begin{bmatrix}A_{II}&A_{IT}\\A_{TI}&A_{TT}\end{bmatrix}.
$$

$A_{IT}$ 表示图像查询读取文字键。不同论文对“text-to-image”的称呼可能按信息流或查询流命名，比较时应始终写清行列对象。

对图像行令 $m_i=\sum_j(A_{IT})_{ij}$，可写：

$$
O_i=(1-m_i)P_iV_I+m_iB_iV_T,
\quad
P_i=\frac{(A_{II})_i}{1-m_i},
\quad
B_i=\frac{(A_{IT})_i}{m_i}.
$$

零质量组单独处理。它说明冻结 $A_{II}$、条件化图像内部路由 $P$、或总图文质量 $m$，约束并不相同。只看一个归一化子图可能隐藏模态竞争；只看模态占比又可能看不见图像内部关系变化。

### 4.3 FreeFlux、Stable Flow、QK-Edit：层选择需要实证

FreeFlux 使用 RoPE 移除／位移干预探测各层对位置的依赖，发现有些层更依赖显式位置，有些更依赖内容匹配。Stable Flow 则筛选影响生成的重要层。这两类证据共同反对“按层号固定解释结构／内容”的简单映射。

QK-Edit 分析多模态注意力子块并选择性使用源视觉 Q/K。对真实图像需要先得到源特征轨迹；合成图像生成过程已知的情况更容易。不能把合成图像的源特征可用性直接当作真实图像免反演条件。

**对姿态／视角的含义**：这些干预能影响布局和关系，但保持源路由过强也可能阻断目标姿态改变。论文的平均编辑指标不能替代“某类任务下某项几何应不变”的明确语义判断。

### 4.4 KV-Edit：背景节点不是完全隔离的节点

KV-Edit 仅为编辑区构造查询，同时让这些查询读取前景和背景的 K/V，背景状态另行保留。这样避免背景跟着条件重新生成，又让新内容能获得上下文。作者还讨论删除任务中背景 K/V 携带原物体信息所导致的残留，并采用重新初始化／mask 引导的处理。[全文](https://arxiv.org/html/2502.17363)。

这是一条重要反例：**“区域不编辑”不等于它的特征不含待删对象信息。** 注意力已经传播过对象语义，背景 K/V 仍可能污染新生成内容。

免反演变体的 $O(1)$ 存储应理解为对采样步数的依赖降到常数，并非对 token 数、层数、分辨率均为常数。固定 latent 区域也不等于逐像素 RGB 严格不变，VAE 解码的感受野会让区域相互影响。

### 4.5 ReFlex、FIA-Edit、ColorCtrl：保留什么比“多注入一点”更重要

ReFlex 从中间时刻提取源特征，适配图像内部／图文交互并注入残差，局部编辑另有基于注意力的区域混合。它提醒源值特征可能造成外观泄漏；“加源信息越多越好”并不成立。[ReFlex](https://arxiv.org/html/2507.01496)。

FIA-Edit 把频率表示交互与特征注入加入免反演 FlowEdit，因而与当前代码主线的机制距离较近。原文评测使用的数据集区域 mask 不应被误判为推理必需 mask；其方法是否满足约束应看实际推理干预，而非仅搜索出现“mask”一词。[FIA-Edit](https://arxiv.org/html/2511.12151)。

ColorCtrl 专门研究“改一个颜色，却影响其他颜色”的问题。结构保留使用图像内部注意力，保色使用非编辑区域的源视觉 V，文字值仍要支持目标颜色。它比一般“结构由 QK、外观由 V”有更具体的任务证据，但内部区域图使其不属于严格无编辑区域掩码方法。[ColorCtrl](https://arxiv.org/html/2508.09131)。

### 4.6 HeadRouter 与 AttnRouter：两个名称相似但不同的方法

HeadRouter 根据源／目标条件的头表示差异路由，再对文字与图像 token 精炼。AttnRouter 则在已有 Qwen 编辑器的同次 forward 中，把清晰源 token 的 K/V 按比例注入噪声 token，并按任务类别选配置。前者主要是头敏感性，后者主要是条件来源与类别路由。[HeadRouter](https://arxiv.org/abs/2411.15034)、[AttnRouter](https://arxiv.org/html/2605.01480)。

AttnRouter 明确比较了 oracle 类别和 CLIP 自动分类；类别真值不能当作部署时免费信息。其加入对象任务可以选择不额外注入源特征，提供“保持过强会妨碍编辑”的直接证据。也不能将其离线配置搜索的成本省略后笼统称完全无需校准。

### 4.7 SpotEdit 与 CacheEdit：编辑保持和加速开始交汇

SpotEdit 早期重建清晰预测，比较其与源图在 VAE 解码特征上的感知差异；相似且稳定的 token 被判作不编辑，绕开 DiT，最后用源 latent 回填。活动区域通过缓存与清晰条件 K/V 融合获得上下文。[全文 §4](https://arxiv.org/html/2512.22323)。

这比普通缓存更直接：普通缓存仍积分所有状态，SpotEdit 对选中的保持区域另有替换操作。但“早期相似”是可错的判断，必要的细粒度属性编辑也可能早期变化很小；最终回填能保持被判定的区域，却不证明判定就是语义真值。

CacheEdit 面向多轮编辑，分析轮、步、层三级冗余，发现可见 latent 差异可能较晚出现，而首步深层激活已经显露编辑区域差异；据此判断哪些 token 可跨轮／跨步复用。[ICML 正文](https://raw.githubusercontent.com/mlresearch/v306/main/assets/yu26e/yu26e.pdf)。

作者报告的不只是速度，也包含结构一致性和指令遵循改善。但收益依赖交互历史、基础编辑器和不变性判别；不能直接外推到单轮、无源条件流、严格无区域选择的 FlowEdit。两者共同说明：**输入、层内激活、输出 latent 的重要性时间点并不一致。**

### 4.8 对应约束为何有助姿态，又为何仍不够

LazyDrag 用用户拖拽给出显式位置对应，再让注意力按对应关系传播，减少反复最近邻匹配的不稳定。ContextDrag 在上下文编辑中处理源—目标位置编码，并在重叠位置抑制冲突条件。[LazyDrag](https://arxiv.org/abs/2509.12203)、[ContextDrag](https://arxiv.org/abs/2512.08477)。

它们说明：当任务涉及移动或姿态变化，仅固定坐标处 token 会把必要编辑冻结；对应需要随几何变化。但用户点对和拖拽区域是额外几何信息，不能当作模型已从不完整文本自动推断。二维位置对应还不等于三维视角、遮挡顺序或实例身份的唯一确定。

### 5.2 DiTF：原始余弦相似可能主要反映共享大通道

DiTF 发现部分 DiT 中间特征在少数固定通道存在巨大激活，且跨多个空间 token 共享，导致原始特征相似性过高。作者通过适当位置的 AdaLN 调制和特征通道处理，改善语义对应和分割等表征任务。[全文](https://arxiv.org/html/2505.18584)。

用一个简单分解可以看清风险：

$$
h_i=b+s_i,\qquad \|b\|\gg\|s_i\|
\quad\Longrightarrow\quad
\cos(h_i,h_j)\approx1.
$$

即使 $s_i$、$s_j$ 分别对应猫眼和背景，它们仍可因为共同大分量而表现出极高相似性。这直接影响特征 kNN 图、合并匹配图和源—目标对应图的可信度。

但“为匹配移除大通道”与“在生成主干中删除大通道”是不同操作。前者改变观测，后者改变生成动力学；不能把 DiTF 的表征收益直接当作主干删通道无害的证据。

### 5.3 massive activation、attention sink、register 不是同一个对象

需要分别讨论：

1. **通道大值**：很多 token 在同一维度都有大值。
2. **高范数 patch token**：只有少数空间节点范数异常。
3. **attention sink**：某些键吸收大量注意力。
4. **显式 register token**：架构加入的额外状态。
5. **隐式语义 register**：原有 token 在中间层获得寄存功能。

Registers Matter 在所测 DiT 中发现的 patch 范数现象不能与 DiTF 的通道大值直接互相否定；两者测量对象不同。其显式寄存器收益也随像素／latent／RAE 表示而变，不能视作统一性质。[Registers Matter](https://arxiv.org/html/2605.16147)。

Text Template Tokens 的工作在 Qwen 家族中表明：输入时语义弱的模板 token，在中间层可能从图像 latent 读回对象信息，成为维持语义的寄存载体。因此，“输入格式 token”不等于“全网络可安全删掉的无用 token”；反过来，“吸收注意力最多”也不直接等于用户指令最关键的词。[核验 v2](https://arxiv.org/abs/2607.19139v2)。

这里的 object identity 主要是生成对象语义承诺的因果分析，不能不加区别地翻译为对某张真实源人脸的身份保持。

### 5.4 EMA 与 STAS：大激活不只是冗余

Awakening DiTs 进一步将 massive activation 的表征副作用和生成作用分开：对匹配，它们可能削弱空间辨别；对生成，部分维度参与细节合成。其 Detail Guidance 通过削弱这些维度得到细节不足的反事实预测，再引导正常预测。MREP 则是另一条特征提取路径。[原文](https://arxiv.org/abs/2607.02968)。

STAS 的核验后期版本把视频首帧／空间边界的大激活与 VAE 编码不对称及残差更新缩放联系起来，再针对这些位置调制。其证据说明 token 显著性还可能来自编码器边界条件，而非对象本身。[v2](https://arxiv.org/abs/2603.17825v2)。

这两项工作意味着：清理图相似性中的共同分量、减小生成计算、增强生成细节，可能要求相反的干预。不能仅因某特征使图变得更“清楚”，就认为在生成时压掉它一定更好。

### 5.5 引导型 token 优化不自动节省计算

HeadHunter 控制注意力头的扰动强度，TPG 用 token 扰动构造弱分支，Sparse Guidance 用稀疏程度构造能力差。它们共同利用“正常预测减弱预测”的差来改善采样，但弱预测本身也要计算。[HeadHunter](https://arxiv.org/abs/2506.10978)、[TPG](https://arxiv.org/abs/2506.10036)、[Sparse Guidance](https://arxiv.org/abs/2601.01608)。

若弱分支足够便宜，总成本可能有利；若新增一次接近完整 forward，则主要是质量改善。更关键的是，通用质量引导可能增强更典型、更清晰的结果，却不保证保留非典型源实例。生成更“好看”与编辑更“忠实”不能互相代替。

### 5.6 训练时 token 关系证据的用途和边界

MDT、MaskDiT 证明隐藏部分 token 再恢复，能促进上下文学习并减少部分训练计算。REPA 对齐外部语义表征，iREPA 则通过多编码器研究强调 token 空间关系对生成学习的作用。[MDT](https://arxiv.org/abs/2303.14389)、[MaskDiT](https://arxiv.org/abs/2306.09305)、[REPA](https://arxiv.org/abs/2410.06940)、[iREPA](https://arxiv.org/abs/2512.10794)。

这些是“空间关系值得研究”的证据，却不是“在既有模型每一步强制保持任意源图关系就会提高编辑质量”的证据。训练目标会让网络适应这种表示约束，推理外挂没有自动获得同样的适应。

### 5.7 空间锚、身份位置与文字语义的补充线索

FreeText 使用 sink-like 文字 token 的空间归因作为定位锚，再利用拓扑细化和噪声／频率匹配的字形注入改善文字渲染。它是“token 锚点用于质量改善”的直接 DiT 先例，但锚的用途是确定在哪里写字，不是保护源图所有未提及信息；推理内部有定位 mask。[原文](https://arxiv.org/abs/2601.00535)。

PosBridge 利用参考图和 FLUX.1-Fill 的上下文布局，把位置嵌入移植到目标位置，改善主体插入的结构和身份一致性。它表明位置编码不只影响“在哪里”，也影响源结构能否正确传递；但需要参考对象与填充区域，且基础方法与附加 LoRA 版本必须分开。[PosBridge](https://arxiv.org/abs/2508.17302)。

Appearance Pointers 学习将文字、图像和用户区域组织成紧凑 pointer token，使条件作用到对应位置；这是区域—条件链接，而不是仅选高注意力 patch。其对应网络需要学习，用户 mask 也是显式输入。“不从头训练骨干”不代表没有训练。[论文](https://arxiv.org/abs/2607.19344)、[作者项目](https://ivl.cs.brown.edu/research/appearance_pointers.html)。

Rare Text Semantics 在联合注意力前调整文字 token 的方差，补充了“增强目标语义”这一侧的证据；Contextual-Space Repulsion 则在条件已吸收图像信息、布局尚未完全固定的位置干预多样性。两者都说明文字 token 在 DiT 中是持续更新的状态，不能只把它们当作静态标签。[罕见语义](https://arxiv.org/abs/2510.03886)、[上下文排斥](https://arxiv.org/abs/2603.28762)。

### 5.8 直接优化 token／调制向量：与选择锚点不同的路线

TokenVerse 不要求从现有 patch 中找一个最重要节点，而是为描述中的不同词优化不同的调制方向，使对象、附件、材质、姿态和光照等概念可以重新组合。调制通过 shift／scale 等通道作用，与只改变文字交叉注意力不同。[TokenVerse](https://arxiv.org/abs/2501.12224)。

Mod-Adapter 使用训练过的视觉语言交叉注意力和 MoE 预测概念的调制方向，减少新概念的测试时微调。它把“逐概念求解”摊销为“训练一个预测器”，因此 tuning-free 仅指部署到新概念时的过程，不能归为不新增任何训练的方法。[Mod-Adapter](https://arxiv.org/abs/2505.18612)。

ResEdit 与此前“源描述不完整”的问题尤其相关：它用额外残差编码保存主要条件没有表达的实例信息，并用梯度反转／对抗优化降低残差对待编辑条件的编码，缓解“重建越强，越难改”的冲突。其主要证据来自固有属性与光照编辑，文字编辑为概念验证；逐图优化与学习式编码器两种版本也要分开。[作者项目](https://johnberg1.github.io/resedit/)、[正式论文](https://doi.org/10.1111/cgf.70551)。

它提供了“把缺失实例信息放进单独 token 通道”的已有先例，不是保证：作者仍报告泄漏、稳定性和身份／可编辑性权衡，且其任务骨干与附加学习不满足当前全部约束。

RaTE 学习可组合的奖励偏好 token；Secretly Knows Restoration 则学习文本编码器输出空间的连续 prompt，并通过扩散桥匹配恢复轨迹。后者还明确区分“输出空间的 prompt 学习”和“文本编码器输入词嵌入优化”，二者可达表示集合不同。[RaTE](https://arxiv.org/abs/2511.20629)、[恢复 prompt](https://arxiv.org/abs/2604.04924)。

Textual Inversion 是冻结生成器、学习概念词嵌入的历史前作，但原论文不是 DiT；不能把其后续 FLUX 实现与原始模型证据混在一起。[原论文](https://arxiv.org/abs/2208.01618)。FreeCus 又采用另一条路线：不逐概念学习词嵌入，而用关键注意力共享和源特征激活定制能力；它使用分割区域减少背景干扰，完整方法还借助 MLLM 丰富语义。[FreeCus](https://arxiv.org/abs/2507.15249)。

从图论解释，这些方法主要改变节点承载的信息及条件到图像的通道，不必显式改变邻接结构。它们对“图节点是否具备足够语义”很有启发，但其学习或额外条件不能在迁移讨论中消失。

## 6. 图论解释：节点重要、关系重要与动力学重要

### 6.1 哪些工作真的使用图论，哪些只是能用图来解释

应保持两级表述：

- **显式图论机制**：例如前一篇报告中的 AT-EDM 使用 Generalized Weighted PageRank；ToMA 明确使用集合覆盖／次模优化。Laplacian 编辑定位和图割合成也有明确图算子。
- **图论重述**：把 ToCa 的注意力影响理解为加权度、把 ResCa 理解为簇内代理传播、把源—目标对应理解为二部边。这是本文的解释，不代表原论文训练了 GNN 或证明了图控制定理。

AT-EDM 的原始实验证据主要是 SDXL 等 U-Net，不能因为用了 PageRank 就把它归为直接 DiT 结果。[AT-EDM](https://arxiv.org/abs/2405.05252)。

### 6.2 加权度、PageRank 与因果影响不是同一个量

令 $A$ 为行随机注意力矩阵。第 $j$ 列的和：

$$
d_j^{\mathrm{read}}=\sum_iA_{ij}
$$

描述该键被查询读取的总权重。若把 $A$ 作为查询到键的随机游走矩阵，PageRank 还考虑多步可达性和重启分布。若按信息实际从 V 流向输出定义边方向，则图方向要相应转置。方向约定不清会把“被读取”误说成“读取其他节点”。

二者都依赖同一组相关性边，未必反映某节点删除对最终图像的影响。局部一阶扰动为：

$$
\delta O=(\delta A)V+A\,\delta V.
$$

只用列和近似重要性，相当于只关注其中非常有限的情形。一般 token 变化同时影响 Q/K/V、softmax、残差、MLP、其他头与后续层；不同 V 方向可能抵消。若最终评价是一个量 $L$，实际敏感方向还取决于：

$$
\delta L
=\left\langle\nabla_O L,\,
(\delta A)V+A\,\delta V\right\rangle+\cdots.
$$

这是解释代理为何可能失败的链式法则，不是本文提出的新重要性算法。一个读取权重高的 token 可能主要承担共用偏置；一个读取权重低的 token 却可能携带人脸中的小痣或车标。

### 6.3 top-k 节点选择与集合覆盖的差别

假设十个最高分 token 都来自同一片高度相似的前景，而某个低分 token 是唯一刻画物体边缘的节点。逐点排序可能集中预算，集合覆盖则会考虑新增代表带来的边际信息。

这解释了三个已有现象：

1. Importance-Based Token Merging 从重要池中保留多样代表，而非只留最强分数。
2. ToMA 使用 facility-location 目标，重视整体覆盖。
3. DuCa 消融中，多样性可以比高分集中刷新更有利。

它们分别优化不同目标，不能把 ToMA 的覆盖保证迁移成任意刷新或源保持的保证。

### 6.4 token 合并是图粗化，但不是严格谱保持

把全节点特征写成 $H$，合并与展开为：

$$
\tilde H=MH,\qquad H'\approx U\,F(\tilde H).
$$

要让粗图近似原计算，除了特征接近，还需要邻域交互、位置与动态响应足够兼容。一般情况下：

$$
F(MH)\ne M\,F(H).
$$

即使有两个 token 的 $H_i\approx H_j$，它们的 RoPE 坐标、邻居、可见性或目标条件响应也可能不同。经过同一粗节点传递会把两条不同的信息路径平均。

图谱稀疏化中的能量近似通常讨论特定 Laplacian 二次型，ToMe 类生成合并并没有自动满足这样的谱条件。不能把“图粗化”的比喻升级成保持所有图频率／生成语义的定理。

### 6.5 稀疏注意力删的是边，token 剪枝删的是计算节点

SVG、SVG2、STA 与 SpargeAttention 通常让输出节点仍存在，只减少某些 query—key 交互；token 合并则改变中间节点数量；ToCa 可让节点保留旧状态；RAS 可让查询减少但仍读取缓存上下文。这些误差来源不同。

局部边有利于空间细节，但远距离左右对称部件、跨对象交互或主体—阴影关系可能需要长边。SVG2 的语义重排能使重要边在硬件上连续，改善稀疏计算效率，却不会自动把所有语义关系都识别正确。

精确 FlashAttention 改变计算／访存组织，在实数算子层面仍计算稠密注意力；稀疏近似删去交互。两者都能提速，但图论含义不同。[FlashAttention](https://arxiv.org/abs/2205.14135)。

### 6.6 时空图能表达“谁跟着谁变化”，但不是天然因果图

ResCa 使用历史轨迹，TaylorSeer 使用历史有限差分，ToCa 使用年龄，CacheEdit 还利用跨轮激活。它们共同说明只看当前时刻的关系不够。

然而同时变化可能来自共同噪声、同一文本条件或全局 AdaLN 调制，不一定是两个部件的真实因果作用。跨时间相似边也不是物体运动对应：缓存的是同一计算索引，运动对应可能把一个源位置关联到另一个目标位置。

TokenFlow 是“按跨帧对应传播特征”的经典先例，但原始骨干为 U-Net 图像扩散，不是名字含 Token 就成为 DiT。它可用于解释匹配与传播的意义，不能替代直接 DiT 编辑证据。[TokenFlow](https://arxiv.org/abs/2307.10373)。

## 7. 哪类图能表达姿态、视角和身份：已有表示的能力比较

本节回答的是文献支持的表达能力和缺失信息，不组装新的综合图，也不规定新的控制算法。

### 7.1 表示能力对照

| 既有图／关系类型 | 有利于表达 | 典型不足 | 对应文献线索 |
|---|---|---|---|
| 固定二维网格／邻接图 | 局部连续、边界、位置保持 | 把必要位移误作漂移；不直接知道语义部件 | STA、DaTMe 的局部性、HiLo-Token |
| 余弦 kNN／聚类图 | 特征重复、候选语义对应 | 大通道主导、左右部件混淆、同类异实例 | ToMe、ToMA、DiTF、SVG2 |
| 有向注意力图 | 当前层信息读取、文字与图像交互 | 层／头差异、sink、公共偏置；不等于因果 | ToCa、HeadRouter、模板寄存器分析 |
| 源—目标二部对应图 | 跨位置保留、移动与局部形变 | 对应错配、遮挡、删除／新增无对应 | LazyDrag、TokenFlow、ContextDrag |
| 动态轨迹／复用关系图 | 短期动态相似、残差传播、刷新历史 | 动态相似可能来自共同条件；未来可分化 | ResCa、JiT、CacheEdit |
| 带节点类型／关系标签的场景图 | 对象、部件、属性归属和交互 | 获取语义关系常需检测／解析或训练 | 前一篇图论报告中的场景图生成 |
| 带方向／相对变换的几何关系 | 朝向、局部坐标、转动和几何一致性 | 变换估计、可见性、三维歧义仍需信息 | RoPE／位置移植、显式拖拽及一般几何理论 |
| 部件／区域级超边或汇聚节点 | 多 token 共同组成对象的高阶结构 | 区域错误会绑定无关内容；可能需训练／mask | Appearance Pointers、区域 token、语义绑定 |

一个关系类型“可表达”某信息，只表示其变量容纳该信息，不代表从现有 DiT token 能可靠恢复它，更不代表施加保持后一定改善编辑。

### 7.2 姿态需要的是部件之间的组织，不只是主体存在

姿态通常涉及关节／部件的相对位置、方向、连接顺序和可见性。只知道若干 token 都是“猫”，不足以区分正坐、回头和侧卧；只知道两眼特征相似，也不足以判断它们的左右关系。

固定坐标对应对无几何变化的颜色编辑较有利，却在“抬起手臂”等任务中阻止必要位移。显式拖拽论文通过用户提供的位置对应绕过一部分歧义，但没有解决不完整描述下自动区分必要／附带姿态变化。

已有数据支持“部件／对应与位置关系具有互补信息”，不支持“所有 token 的原位置都必须保持”，也不支持“只要语义匹配就可以忽略空间位置”。

### 7.3 视角需要观察方向、遮挡与有序关系

车辆前视／后视可能在全局“汽车”语义、局部材质相似性、甚至部分轮廓上都接近。二维关系中的“灯在车轮上方”也未必足以区分车头和车尾。

只由成对距离得到的图，对刚性转动、平移和镜像存在不变性；这些不变性有时希望保留，有时恰好抹掉视角差异。单张源图没有提供背面可见内容，任何图都不能凭表示形式消除遮挡导致的信息缺失。

FreeFlux 的 RoPE 探测、PosBridge 的位置移植、ContextDrag 的位置对齐都提供位置通道会影响结构的证据。DiTraj 则通过前景 token 的 3D-RoPE 修改实现视频轨迹控制；但它使用轨迹输入、前景／背景区分和 LLM 提示分解，不能当作满足当前严格约束的自动视角保持方法。[DiTraj](https://arxiv.org/abs/2509.21839)。

### 7.4 身份需要区分类内实例，而不只是类别一致

“仍然是一只猫”“仍然是同一品种”弱于“仍然是源图那只猫”。小斑纹、眼形、鼻梁、车标或特殊损伤可能决定实例身份，却不是文字条件最敏感的位置，也未必是全图最大的激活。

Personalize Anything、PuLID-FLUX、InfiniteYou 的直接身份结果依赖主体参考／训练模块，说明身份保持有专门信息需求。源图已有的信息与额外身份参考应区分，但无论来源如何，图节点必须实际承载能区分实例的观测；仅提升图的复杂程度不能制造未被特征编码的信息。

模板 token 中的“对象身份寄存”有助理解生成语义的存储位置，却不能替代真实实例身份判别。类别承诺、个体身份和像素一致性是三个层次。

### 7.5 属性绑定需要归属关系，而非只提高目标词注意力

把“红色”词的注意力整体放大，可能让多个对象同时变红；提高目标对象 token 的重要性，也未必阻止属性经共享条件传播到其他对象。需要区分“某属性被表达”和“该属性属于哪个对象”。

语义绑定 ToMe 把对象及其属性／子对象聚合成复合文字 token，并用辅助目标更新；它与加速 ToMe／ToMeSD 同名但不同。原始主要证据来自 U-Net 系统，是关系绑定的邻近前作，不作为直接 DiT 编辑保证。[语义绑定 ToMe](https://arxiv.org/abs/2411.07132)。

ColorCtrl 针对颜色误改，Appearance Pointers 显式链接区域与条件，Rare Text Semantics 增强罕见条件表达。这些解决的是不同部分：归属、位置和条件强度不能相互替代。

### 7.6 文献支持的必要性质，而非一种已确认的最优图

对目标“表达姿态／视角／身份，同时允许指定编辑”，现有结果至少要求保留以下区分：

| 必要区分 | 若忽略，已有证据或反例是什么 |
|---|---|
| 特征内容与显式位置 | FreeFlux／PosBridge 表明二者共同影响结构 |
| 单节点分数与整体覆盖 | ToMA／DuCa 表明集中保留高分并不总好 |
| 当前特征与历史动态 | ResCa 表明动力学相似比单点特征相似更适合某些代理 |
| 目标条件敏感与源实例保持 | CFG 弱响应处仍可能有 DaTMe 关注的重要结构 |
| 文本语义、格式与中间寄存功能 | 模板 token 的功能会在网络内部改变 |
| 可匹配部分与新增／删除／遮挡 | ContextDrag／KV-Edit 显示对应冲突和旧语义残留 |
| 当前代理下降与真实任务完成 | 本项目已有真实实验出现代理改善但视角仍错 |
| 计算近似保真与编辑语义正确 | 普通文生图加速的 FID／PSNR不能证明源保持 |

从这些性质仍不能推出具体应选多少节点、哪些边、什么权重或如何干预；这些属于方案阶段，本轮不展开。

## 8. 数学辨析：哪些图不变量会漏掉漂移

以下是对已有图量的标准分析和反例，不是新编辑目标。

### 8.1 单节点标量不能独立表达部件关系

若只保留每个 token 的一个重要性标量 $s_i$，即使知道高分位于若干部件，也不知道部件之间谁在左、谁在前、谁被遮挡。

更基本地，两个源实例可以具有相同的重要性图，却有不同的 V 方向、局部纹理和身份。重要性图最多说明“某种代理认为哪里值得算”，不能成为完整语义状态。

### 8.2 Laplacian 保持看不见其零空间

对无向连通图的标准 Laplacian $L$：

$$
L\mathbf1=0.
$$

若所有节点特征都增加同一向量 $b$：

$$
H'=H+\mathbf1b^\top,
\qquad LH'=LH.
$$

因此只观测 $LH$ 会漏掉公共特征偏移。若有 $k$ 个连通分量，则各分量还有独立常量零空间。某种身份／风格变化若主要落在该不可见子空间，Laplacian 量不变也不能否定漂移。

这不表示 Laplacian 无用，而是它刻画相对变化，不能承担完整状态识别。

### 8.3 Gram／距离关系有坐标和对称歧义

令 $H$ 的每一行是一个节点特征，$R$ 为正交变换：

$$
H'=HR,\qquad H'H'^\top=HH^\top.
$$

所以仅由 $HH^\top$ 得到的关系看不见特征空间整体正交变换；成对空间距离还看不见平移、转动与镜像。真实视角改变未必严格落在这些对称变换中，但这已足以否定“关系相同必然语义相同”的普遍命题。

若还允许重排节点并只比较无标签图的谱，左右部件交换和重复结构会更难区分。图谱相似比具备固定节点对应的完整关系更弱；非同构图也可能同谱。

### 8.4 相似 token 不一定可交换

即便 $H_i=H_j$，加入不同位置编码后也可能有：

$$
\operatorname{RoPE}_{p_i}(Q_i)
\ne
\operatorname{RoPE}_{p_j}(Q_j).
$$

它们对同一键的注意力不同，后续响应不同。源图中两个相似车轮，一个位于近处、一个远处，不能仅凭余弦相近而合并成同一个语义位置。

此外，局部导数也可能不同。两个状态当前值接近，不意味着面对目标条件的变化率相同。ResCa 转向历史轨迹而非静态特征聚类，正是这一问题在加速中的实证体现。

### 8.5 softmax 的规范不变性与共享偏置

逐行 softmax 满足：

$$
\operatorname{softmax}(z_i+a_i\mathbf1)
=\operatorname{softmax}(z_i).
$$

若同一偏置向量加入该行**所有**键，产生的共同 logit 位移不改变注意力。若只加到图像键，文字键未变，则会改变图像／文字的总质量竞争；RoPE 若在不同位置施加，原本共享的投影偏置也未必在旋转后仍共享。

因此 DCAG 等 bias-delta 分析必须说明：在哪个投影阶段分解、修改哪些 token、哪些组参与 softmax，以及位置变换如何作用。不能脱离这些前提写成“共享 K 偏置总能改变路由”或“共享 K 偏置永远无效”。[DCAG](https://arxiv.org/html/2602.18022)。

### 8.6 对应平均会抹平实例信息

若一个目标 token 被两个源 token 以 $1/2,1/2$ 软匹配，传播结果为：

$$
h'_i=\tfrac12h_a+\tfrac12h_b.
$$

当 $h_a$、$h_b$ 含有不同细斑纹或身份细节，平均值可能对应两者都不像的状态。软匹配更平滑，不代表更忠实；硬匹配也可能选错节点。

这说明匹配置信度、唯一性和可见性是解释现有方法时必须识别的信息。本文不据此定义新匹配器。

## 9. 黎曼几何与信息几何：可解释什么，不能保证什么

### 9.1 token 特征诱导的度量取决于观测

给定已有特征映射 $\phi(y)$，加权欧氏距离的局部拉回为：

$$
ds^2=d\phi^\top W\,d\phi
=dy^\top G(y)\,dy,
\qquad
G=J_\phi^\top WJ_\phi.
$$

若 $J_\phi$ 不满列秩，$G$ 只是半正定，存在特征看不见的状态方向；把它称作完整黎曼度量需额外条件。在一般生成流形几何中，拉回度量和沿流形的距离／平行移动已有成熟研究。[Shao 等](https://arxiv.org/abs/1711.08014)。

用于本调研的含义是：换成 DiT token 空间并不会自动解决可观测性。特征若区分不了车头与车尾，沿该特征度量的短路径仍可产生错误视角；若身份差异处于低敏感方向，几何距离小也可能已换实例。

### 9.2 对什么不变，是任务决定的问题

假设某表示对变换群 $\mathcal G$ 不变，即 $\phi(g\cdot y)=\phi(y)$。这有助消除无关变化，也意味着不能检测该群内的变化。

例如：希望编辑颜色而保持姿态时，对姿态过度不变会漏检；希望改变姿态但保持身份时，对位置太敏感又会把必要变化当成损坏。商空间可以形式化“把哪些变化视为等价”，却不能自行决定用户意图。

因此“用更强的不变图更稳”没有普遍依据。已有几何控制和对应工作需要任务、参考或交互信息来确定可接受变化。

### 9.3 标量图扩散与带方向的几何输运

普通加权图扩散传播标量或按通道传播特征。若节点表示来自不同局部坐标系，直接平均向量可能没有几何意义。Vector Diffusion Maps 使用带局部正交变换的连接结构，联系到流形上的 connection Laplacian 与向量场热核。[Singer 与 Wu](https://arxiv.org/abs/1102.0075)。

这是“几何关系比相似性权重更丰富”的一般数学先例：边不仅可以表示多相似，也可以表示局部方向如何对应。它适合解释为何姿态／视角问题不能只依靠标量关联强度。

但它不是已经在本项目 DiT 编辑中验证的方法。局部框架、变换和有效对应必须从观测中得到；错误变换会把错误结构传播得更一致。引入连接几何也不会凭空获得真实相机姿态或隐藏面的信息。

### 9.4 注意力分布的 Fisher／KL 只度量读取概率

对正的注意力行概率 $p$，小扰动 $\delta p$ 的 KL 二阶近似为：

$$
\mathrm{KL}(p\,\|\,p+\delta p)
\approx\frac12\sum_j\frac{(\delta p_j)^2}{p_j},
\qquad \sum_j\delta p_j=0.
$$

这可解释为何低概率边的相对变化和高概率边的绝对变化具有不同权重。但它测量的是注意力分配变化，没有包括 V 内容：

$$
A'=A,\quad V'\ne V
\quad\Longrightarrow\quad
O'=AV'\ \text{仍可改变}.
$$

反过来，若不同键的 V 相同，改变分配也可能不改变输出。注意力 KL 小不意味着图像语义保持，注意力 KL 大也不必然表示不该发生的变化。此前文档的联合分布分解可用于解释这种层次差异，不应被误读为语义保持定理。

### 9.5 “流形切向”也可能包含身份漂移

若某条改变身份的路径本来就是模型生成流形上的合法路径，要求运动留在切空间不会禁止它。黎曼几何能区分某些离流形伪影，却不自动区分“合法但不符合源实例”的结果。

同理，测地线最短对应给定度量的最小长度，不对应“语义编辑最准确”。度量、任务端点和实例对应若未定义，不能用“最短路径”替代正确编辑目标。

## 10. 概率流与动力学：加速保真和编辑正确性的区别

### 10.1 注意力随机游走不等于生成概率流

注意力行和为一，可以形式上作为有限节点上的转移矩阵；概率流 ODE 的密度则位于整个图像／latent 状态空间：

$$
\dot y=f(y,s,c),
\qquad
\partial_s p_s=-\nabla_y\cdot(p_sf).
$$

两种“流”的状态空间不同。对 token 图做一次扩散或保持 PageRank，不等价于保持 $p_s$，更不等价于保证给定源图的正确编辑。[Score SDE](https://arxiv.org/abs/2011.13456)、[Flow Matching](https://arxiv.org/abs/2210.02747)。

本节用 $s$ 表示沿实际采样方向增加的参数，避免把不同论文的“0 是噪声／0 是数据”约定混为一谈。

### 10.2 缓存、合并和稀疏计算都在改变速度场

将加速后的场写成：

$$
\tilde f(y,s)=f(y,s)+e(y,s).
$$

对接近的两条轨迹，一阶误差满足：

$$
\dot{\delta y}
\approx J_f(y,s)\delta y+e(y,s).
$$

令 $\Phi(s,r)$ 是线性化状态转移算子，则：

$$
\delta y(S)\approx
\Phi(S,0)\delta y(0)
+\int_0^S\Phi(S,r)e(y(r),r)\,dr.
$$

这解释：

- 当前 token 误差小，仍可能沿后续敏感方向放大。
- 相似特征不等于相似速度，更不等于相似未来影响。
- 不同层和不同时刻的相同误差，最终后果不同。
- 按历史缓存年龄、阶段敏感度或残差预测分配计算，有明确数值动机。

ToCa、SODA、TaylorSeer、ResCa 分别在不同层面处理这些问题，但它们主要近似原生成轨迹。若原轨迹已经有视角或身份漂移，近似得更准确仍可忠实保留该错误。

### 10.3 两个编辑分支的误差相关性不能忽略

FlowEdit 类编辑含源／目标条件场的差。若两分支的近似误差分别为 $e_t,e_s$，差场误差为：

$$
e_{\mathrm{edit}}=e_t-e_s.
$$

其二阶量含交叉项：

$$
\mathbb E\|e_t-e_s\|^2
=\mathbb E\|e_t\|^2+\mathbb E\|e_s\|^2
-2\mathbb E\langle e_t,e_s\rangle.
$$

所以单分支生成的缓存指标不足以预测编辑影响：共同误差可能抵消，不同的选择／匹配误差也可能破坏原有抵消。这个代数事实不构成本文新的缓存策略，只限定现有加速论文外推到编辑时的证据范围。

### 10.4 轨迹相似不是跨条件可交换

ResCa 的历史簇在固定生成条件下有经验依据。编辑若改变某一对象的材料或动作，同簇 token 的后续动力学可能分叉。过去几步同向，可以来自共同噪声衰减，也可以来自同一部件；两者的未来可迁移性不同。

JiT 对全状态速度的空间提升，同样需要局部变化可由锚点合理近似。若缺失 token 是细小而重要的身份标记、远距离纹理对应或刚出现的新对象，空间平滑插值没有一般恢复保证。

### 10.5 清晰预测是估计，不是真实编辑终点

SpotEdit 和 DaTMe 使用的 $\hat x_0$／清晰预测具有实用价值：它把噪声量转为更接近视觉内容的观测。但它通常是当前条件下的模型估计，不是已知最终真实图像。

对线性噪声路径，后验均值式估计混合多个可能解释；在多模态情况下，均值可模糊细节，后续采样也可选择不同模式。不能从“清晰预测稳定”直接推出“身份正确且无需编辑”。

对训练条件路径为直线的 Rectified Flow，也不能说每条实际边缘 ODE 样本轨迹都严格直线。训练的条件速度是端点差，学习的边缘速度是条件平均；有限模型误差和多模态条件还会进一步影响轨迹。

### 10.6 分布正确不等于源—目标配对正确

设两张源图分别为 $a,b$，目标分布也只含两种对应实例 $a',b'$。映射 $a\mapsto a',b\mapsto b'$ 与交换映射 $a\mapsto b',b\mapsto a'$ 可以产生完全相同的目标边缘分布，但实例对应相反。

因此，即使生成分布、FID 或某种概率流边缘密度都正确，也未必实现用户要求的源实例保持。编辑问题还涉及特定耦合：哪一个源实例应该到哪一个合法目标实例。

只靠同一文本条件或全局类别 token 无法一般地确定这个耦合。图方法若要声称身份保持，需要有能区分配对的观测证据，不能仅引用分布级生成结果。

## 11. 为什么现有方法尚不能同时“保证无关区域不改”和“保证目标正常编辑”

### 11.1 保持信息与改变信息可能重叠

对“猫变成狗但姿态保持”，猫脸部件中的某些特征必须改变，身体相对关系可能应保留；对“改变头部朝向”，同一批空间位置又必须移动。编辑和保持不是预先互不相交的通道。

完整源 token 或全部关系强冻结，可能阻断目标转换；只强化文字相关 token，又可能忽略实例细节。这与此前项目中全局关系代理改进但真实视角仍失败的结果一致，不能用更复杂的图名替代这个矛盾。

### 11.2 “不相关区域”不等于所有像素都不应该变化

添加物体可能需要改变邻近阴影、反射、遮挡；改变光照可能影响全图；移动对象需要补全露出的背景。Add-it 便明确希望保留插入产生的合理附带效果。

所以现有 mask 方法的区域定义也是一种任务假设，不能在所有编辑类型上给出精确边界。没有显式区域信息时，依赖模型判断仍有语义误差。

### 11.3 自动区域选择存在漏改与误改两种风险

SpotEdit 的早期稳定性、CacheEdit 的激活差、ColorCtrl 的词注意力都在估计“哪里应改”。估计错了：

- 把必要编辑区域判为保持区，会出现漏改或不足编辑。
- 把应保持区域判为活动区，仍会发生额外变化。
- 若目标对象的旧语义已传播到背景特征，保持背景 K/V 也可能阻碍删除。

因此，实验中取得更好的质量／速度折中，不等于判别在每个样本上正确。

### 11.4 冻结权重也可能大幅改变有效模型

替换 Q/K/V、删边、合并 token、改变位置编码、回填源状态都可在不更新权重时改变前向函数。无训练的含义是没有学习参数，不是保持原生成分布不变，也不是风险为零。

相反，AnchorCache 展示了更强的结构改造：静态文字锚和注意力布局使参考分支可以精确缓存，但为恢复改造引起的质量变化，仍进行了教师强制及 on-policy 蒸馏。[核验 v3](https://arxiv.org/abs/2608.21229v3)。

### 11.5 目前能支持的最强结论

已有文献支持：

1. DiT token 中存在可利用的数值、空间、时间和条件冗余。
2. 重要性＋代表覆盖＋动态刷新，比单纯相似性或固定预算更丰富。
3. 源条件 token、特征注入与对应关系能改善某些编辑保持问题。
4. 编辑专用的 token 路由／缓存，在特定骨干和任务上可以同时改善效率和一致性。
5. 单节点重要性、单层注意力和全局关系代理，都不足以单独保证姿态、视角、真实身份和任务完成。

**在本轮核验的文献中，尚未发现一项已经证明：在任意预训练 DiT／流模型上，无训练、无内部编辑区域掩码、无额外参考／对齐模块、免反演地处理不完整描述，并对无关变化抑制和目标编辑完成同时给出普遍保证。** 这是一项有检索边界的结论，不是对未来可能性或全部未检索文献的否定。

## 13. 文献脉络与查阅入口

### 13.1 重要性与锚点脉络

相似合并前作 ToMeSD → CFG 重要性合并 → ToMA 的覆盖与矩阵化 → DaTMe 的动态／结构双观测，是“谁作为代表”的一条脉络。ToCa → DuCa／SODA 是“谁何时重新计算”的另一条脉络。ResCa 和 JiT 则把锚点分别用于残差代理和速度场近似。三条脉络存在交叉，目标和保证并不相同。

对应主文献：[ToMeSD](https://arxiv.org/abs/2303.17604)、[重要性合并](https://arxiv.org/abs/2411.16720)、[ToMA](https://arxiv.org/abs/2509.10918)、[DaTMe](https://arxiv.org/abs/2610.22370)、[ToCa](https://arxiv.org/abs/2410.05317)、[DuCa](https://arxiv.org/abs/2412.18911)、[SODA](https://arxiv.org/abs/2603.07057)、[ResCa](https://fanghaipeng.github.io/ResCa/)、[JiT](https://arxiv.org/abs/2603.10744)。

源特征控制 → 位置／多模态子块分析 → 编辑区域的保留与重算 → 跨轮复用，是更接近当前问题的一条脉络。参考条件压缩与静态缓存接口是并行支线。

对应主文献：[Stable Flow](https://arxiv.org/abs/2411.14430)、[FreeFlux](https://arxiv.org/abs/2503.16153)、[QK-Edit](https://arxiv.org/abs/2610.17829)、[KV-Edit](https://arxiv.org/abs/2502.17363)、[FIA-Edit](https://arxiv.org/abs/2511.12151)、[ColorCtrl](https://arxiv.org/abs/2508.09131)、[SpotEdit](https://arxiv.org/abs/2512.22323)、[CacheEdit](https://proceedings.mlr.press/v306/yu26e.html)、[ToPi](https://arxiv.org/abs/2602.01609)、[OminiControl2](https://arxiv.org/abs/2503.08280)、[AnchorCache](https://arxiv.org/abs/2608.21229)。
