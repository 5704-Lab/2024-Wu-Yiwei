## 2. 模型与积分接口已核查的事实

当前本地 SD3 Medium 配置为：24 个 block，24 个 attention head，head 维数 64，图像／文本共同 hidden 维数 1536；VAE 潜变量 16 通道，patch size 2，文本输入维数 4096，池化条件维数 2048。

对于 512×512 图像，潜变量为 16×64×64，attention 图像 token 为 32×32，即 1024 个；不能把潜变量网格数与 attention token 数混同。实际文本长度从编码结果读取，不固定假设 77 或任意模板位置。

已核查的本地入口：

- `vendor/flowedit/FlowEdit_utils.py`：`FlowEditSD3`、`calc_v_sd3`。
- `.venv/lib/python3.12/site-packages/diffusers/models/attention_processor.py`：`JointAttnProcessor2_0`。
- `.venv/lib/python3.12/site-packages/diffusers/models/attention.py`：`JointTransformerBlock`。
- 旧 `experiments/semantic_feedback_20261028/extract.py` 读取 block 图像残差并压到 8×8；不是本方案需要的原生共同输出空间。
- 旧 `repair.py`／`full.py` 提供潜变量求导、原始基线和积分同步经验，但其旧残差与消元方式不直接继承。

`calc_v_sd3` 内部有 `torch.no_grad()`，适合原名义速度，不可直接用作观察器的可微入口。观察器直接调用冻结 `SD3Transformer2DModel`，参数不求梯度，输入 y 保持计算图。

## 3. 数据结构与固定源缓存

建议以下接口，类型签名为实现规范：

```python
@dataclass(frozen=True)
class ProbeKey:
    checkpoint_config_hash: str
    model_weights_fingerprint: str
    vae_and_latent_convention_hash: str
    source_latent_hash: str
    prompt_embedding_hash: str  # 序列与 pooled 都包含
    concept_bank_hash: str
    fact_schema_and_normalization_hash: str
    extraction_code_hash: str
    attention_processor_and_backend_hash: str
    library_and_kernel_fingerprint: str
    tau: float
    noise_hash: str
    height: int
    width: int
    layer: int
    facet: str
    dtype: str
    coordinate_convention: str

@dataclass
class NativeObservation:
    image_outputs: dict
    context_outputs: dict
    concept_outputs: dict
    image_attention_mass: dict
    coordinates: object
    diagnostics: dict

@dataclass
class FactReadout:
    values: object
    source_values: object
    source_scales: object
    tolerances: object
    supported: object
    binding_diagnostics: dict
```

源缓存只在初始化时生成，可 detach、转 CPU。当前观测在求导分支不得 `.detach()`、`.cpu()` 或用 no-grad 包住。图像尺寸、文本编码、噪声或 dtype 改变必须产生新缓存键，不能复用旧源值制造假小残差。

审查补充：仅有架构配置哈希不能区分权重，旧键也遗漏了源潜变量本身；即使提示相同，不同源图必须产生不同缓存身份。概念库、测量规则和提取后端也属于测量定义，必须参与缓存身份或强制缓存失效。

源事实、容差、词组库、任务范围和归一化尺度在本轨迹固定。当前状态负责测量偏差与任务进度，不反过来扩大许可或更新源参照。

## 4. 如何提取真正可比较的 O、C 和 B

### 4.1 O/C 的位置与单位

图像 O 的投影前输出可由 `attn.to_out[0]` 的 forward pre-hook 获得；普通 block 的文本 C 投影前输出由 `attn.to_add_out` 的 pre-hook 获得。两者处于同一个 head 拼接后的 attention output 空间，可再按 head reshape。

直接 hook `attn` 返回的是经过不同输出投影的图像／文本模块输出。整个 block 返回的文本值又经过 gate 和 MLP，不能与前者混为一谈。跨图像比较同一 facet 可以做；跨模态点积必须保证处于共同的投影前空间，不能仅凭维数相同。

最后一个 `context_pre_only` block 不走普通文本输出投影，block 文本残差也可为 `None`。第一版选择 3、11、20 层（零起始索引），不读取末层，仍在元数据登记该差异。未来包含末层时须单独处理，不能把空值补零。

Q/K/V 对照使用原投影和原 q/k normalization 的结果。若只 hook `to_q/to_k`，得到的是 normalization 前值，必须明确区别。图像和文本分别使用原投影权重，不改原 attention 输入。

### 4.2 只读概念流

概念初值使用现有文本编码器的指定 token 表征，经过原 context embedding 接口进入 1536 维。记录 tokenizer、子词位置、pooling 与特殊 token 规则；多词短语先作为单独消融，不预设平均 embedding 有可靠关系语义。

在各 block，旁路复用该 block 的文本侧 norm、q/k/v 投影、输出投影、gate 和 MLP；query 读取原图像 K/V 与概念自身 K/V。原图像／原提示绝不读取新增概念。使用主观测共同条件的 temb／pooled 调制，不另改原网络条件。

动态概念流必须连续经过从首层到所读层的全部 block；只在 3、11、20 层挂提取钩子不足以传播该流。可以只保存三层结果，但中间层的旁路更新不能省略。不同 attention processor 的实际调用位置还需运行时核查，不能仅凭类名推断 pre-hook 一定触发。

旁路最好在 hook 回调中独立计算少量 concept-query 的 attention，不向原序列追加 token，以保持原 kernel 路径。只保存所需层的中间量。记录概念对图像的总质量 α，再计算条件空间分布及位置矩；不可只返回归一化定位图。

源冻结 query 和动态 query 两种版本独立比较。源冻结版本的源 query 为常量，当前 K/V 仍可微；动态版本须让当前 query、key、value 及概率都进入导数。

### 4.3 纯函数与求导约束

提供 `observe(y, probe_bank, source_cache) -> NativeObservation`，每次调用拥有独立捕获上下文。禁止全局保存“最后一次 feature”导致多次 JVP 或并发调用串线。不沿用旧实现中靠异常提前结束 forward 的控制流；需要 prefix 提取时，单独实现并先做完整 forward 一致性验证。

原名义速度维持原后端和 dtype。观察器最初用 FP32；JVP/VJP 若使用数学 SDPA，应在独立作用域记录。只读性首先在相同后端逐查询比较，不把后端差异算成方法影响。

## 5. 事实测量的第一版

### 5.1 实例绑定

共同提示、共同概念词组与固定源节点一起定义对象。源／当前的双向对应、部件语义和源坐标共同识别实例，不能仅用类别名找最近邻。重复对象绑定歧义、低图像质量支撑、遮挡导致的缺失都要输出诊断。

只读空间概率是测量工具，不阈值成编辑区域，不与速度逐空间相乘。当前 mask-free 条件不阻止正常注意力计算，但不允许把这些权重变成更新门控。

### 5.2 首批事实与失败条件

| 事实候选 | 计算方式 | 必须拒绝硬控制的情况 |
|---|---|---|
| 吻—头方向 | 位置差归一化，或相对源方向的局部角度 | 两点重合、错误对象绑定、遮挡或双向不一致 |
| 头—躯干关系 | 相对方向与源尺度归一化的偏移 | 合法形态下同量显著漂移，无法分清头部／躯干 |
| 对象间关系 | 源实例节点的相对坐标与角色 | 两个对象被平均，或视角／面积变化主导分数 |
| 背景与场景 | 背景概念和源对象关系分布 | 把合法遮挡差异误当场景替换，或响应主要来自查询自身 |
| 朝向的补充证据 | 眼部次序、部件可见性、成对姿态假设 | 不能区分正／背两方向或只随提示改变 |

二维事实不是三维姿态真值。事实不足时记录保护覆盖范围，不能将缺失值补为零残差并统计为成功。

方向量还需避免坐标框偏差：把单位向量各分量分别放入同一宽度区间，会得到依赖坐标旋转的接受结果。第一版标量控制器应接收有局部角度定义的源相对角度；向量方向需用成组 L2 约束及对应角度容差，不能用逐分量盒约束冒充相同的角度限制。角度跨分支切口时须重新验证可微性，不能套用全局光滑假设。

若原先受保护的事实中途失去支撑，不得删去该行后继续声称完整恢复保证；应记录观测失败及保证中断。继续无控制提议的样本可单列统计，不能与被约束成功的样本合并。

### 5.3 校准

先复用已有受控数据，明确其为玩具形态任务，不算物种替换验证。相机两侧、两种转头、形态正例、错误对象及背景因素分别评估。

在开发组选择 facet、层、时刻和词组；校准组锁定源尺度规则与容差；新源和种子作留出。源尺度可来自固定身体长度／噪声稳定性，不能依赖每个测试源的正确目标图。多种子重复性只测采样波动，不提供语义偏差界。

## 6. 任务完成读出与文本范围

第一版显式声明三个任务：只改色、类别形态改变、明确转头。固定任务协议指定需要改变和保护的事实；不把它报告为任意文本解析。

类别任务至少独立检查：全文兼容、正确对象绑定的目标概念、完整形态相对仅改色。根据原生 B 与已有 SigLIP2 各自的困难负例辨识结果决定是否可用于任务梯度。不能把新 B 的任何输出直接称为已验证任务分数，也不继续单独使用旧全局 target-minus-source margin。

任务已经完成时保护其完成集合，避免要求无限增加同一分数。任务未完成时，本步下界采用速率或与 h 成比例的增量；多个分数分别约束，防止相互补偿。

对自由文本，源／目标变化片段和固定词库只提出候选查询，不能据 embedding 相似度直接授权。若请求明确改变姿态，旧姿态保持约束必须按请求调整；若范围无法可靠判断，记录接口未覆盖。当前不新增 LLM 或训练读出器弥补这一缺口。

## 7. 参考控制器与正式求解接口

### 7.1 已实现的数学接口

```python
solve_local_step(
    residual=r, jacobian=J, raw_increment=d0, step_width=h,
    tolerance=beta, recovery_rate=eta,
    metric_diagonal=Mdiag,
    task_gradients=G, task_rate_floor=p,
    relation_curvature=Lk, task_curvature=Le,
    correction_speed_limit=Umax, total_speed_limit=Vmax,
)
```

它求解 $v=d/h$，保证标量观测的线性／余项模型满足

$$|r_j+hJ_jv|+\tfrac12L_jh^2\|v\|_M^2
\le\beta_j+e^{-\eta_jh}(|r_j|-\beta_j)_+,$$

$$G_iv-\tfrac12L_{E,i}h\|v\|_M^2\ge p_i,$$

并限制修正速度和总速度。返回不可行状态，不添加隐式 slack、不裁剪解；诊断明确标记尚未进行有限非线性验收和语义认证。

审查后增加两层防漏：任务下界／曲率若没有对应梯度必须报错；求解器返回后重新逐项计算关系、任务、修正速度与总速度误差，超过登记的数值容差则拒绝候选。`optimal` 或 `optimal_inaccurate` 标签不单独作为约束满足证据。没有任务约束时在诊断中显式记录，真实编辑调用方仍须禁止把这种参考求解当作联合编辑控制。

L 必须是归一化测量在固定 M 范数下的二阶界；原始特征或像素欧氏范数中的界不能不经换算直接传入。默认 L=0 只表示采用一阶候选模型，不表示真实网络曲率为零。

此参考实现使用本地已有 CVXPY／CLARABEL，面向小规模构造问题，不直接显式构建真实高维 SD3 Jacobian。

### 7.2 正式潜变量求解

对于少量事实，局部线性部分的修正位于 $M^{-1}J^T$ 与任务梯度张成的空间。可先用 VJP 构造少量梯度，再在这个动作子空间求低维凸问题；记录这是否限制了最优解。

无额外曲率项、M 为固定正定度量且目标为最小偏离时，最优修正在活动约束行空间内。加入总速度界后，该界还作用于原名义动作的法向／切向分量；子空间须包含名义动作或在约束中完整处理它，不能只截取梯度后当原全空间等价。

矩阵自由版本提供 `jvp(d)` 与 `vjp(w)`，形成 Gram 运算并求对偶／小规模锥问题。每次 VJP、JVP 数量、显存和耗时都单独计入。不能以“无新增参数”宣称计算免费。

### 7.3 未知曲率界与验收

真实模型的 L 先不当已知常数。采用固定预算信赖域、有限差分检查和候选重计算。任务、关系和动作预算全部验收，通过后才更新实际 y。

在构造 Jacobian 前可先验收原提议：若实际有限观测已经满足任务、恢复目标与预算，直接接受零修正，不调用控制求导。参考控制器也在局部模型中先检查名义动作可行性，此时零修正代价严格最优。

对当前非法事实要求越界部分按目标收缩；对当前合法事实只要求保持容差。没有出现新错误且原提议满足目标时，应允许零反馈。若回溯或缩放修正，必须重新检查全部条件，不能只看能量下降。

## 8. FlowEdit 中的插入点和后端一致性

原循环的本步提议为

$$q_s=(1-t)x_0+t\epsilon_{FE},\quad q_t=y+q_s-x_0,$$

$$d_0=(t_{next}-t)\,[v_{tar}(q_t)-v_{src}(q_s)].$$

本方案在当前 y 建模约束，对整个增量 d 求解，最后赋值 `y = y + d`。不要先不可逆地写入原更新再丢失当前残差；若采用原提议后再校正的版本，必须明确线性化点及任务／保持参考不变，并单独评价。

接受后，下一步重新计算 `q_t = y + q_s - x0`。不能只改图像或旧预测、保留过时目标查询。观察器使用独立的固定探测银行，不能误用 `q_t` 代替标准重加噪。

首版固定原时间网格、FE 随机数、CFG 和无控制路径。对原有非零 `n_min` 常规采样尾段，当前变量不再全部等同同一干净编辑坐标，须另行定义后才能接入；第一版只覆盖已验证的耦合 FlowEdit 区间。

## 9. 开销与缓存估算

起始候选为 3、11、20 层，$\tau\in\{0.20,0.35\}$，2 个控制种子及独立审计种子，一个共同提示。层在同一次 forward 中提取，不把三层错误计为三次完整查询。

每次探测 forward 可缓存多层，但反向保存中间量会增加显存。512 图上单个 1024×1536 FP32 图像 facet 约 6 MiB；3 层×2 时刻×2 种子约 72 MiB，仅为这一 facet 的源缓存，不包含 K/V、文本、B、模型和反向激活。1024 图的该部分约再乘四。

先逐探测配置运行并流式汇总小维事实，源大特征存 CPU；求导按配置累计，必要时重算，避免一次保留全部图。运行实测峰值显存后再确定批大小，不预占 GPU、不猜测吞吐。

## 10. 实现顺序与准入条件

| 阶段 | 交付 | 必须通过的判断 |
|---|---|---|
| A 接口 | `tap.py`、`probe.py`、缓存协议 | 无控制原速度一致、恒等配对零残差、O/C 位置与单位明确 |
| B 测量 | `facts.py`、绑定与内容错配诊断 | 跟随当前干净图；允许合法形态；两方向转头均可测 |
| C 校准 | `calibrate.py`、锁定的 `calibration.json` | 跨源容差有效；不能用面积、文本自身或噪声伪对应替代事实 |
| D 短程 | `linearize.py`、`controller.py`、`accept.py` | 正确状态不额外拉回，错误状态修复且不撤销形态 |
| E 完整 | `run_flowedit.py`、独立审计 | 相近实际完成度下减少无关修改，收益不能仅由缩步解释 |

若 B／C 失败，停止扩大闭环调参并报告观测瓶颈。若 D 不可行，分别检查可控性、预算和任务读出，而不是扩大源容差。完整阶段含无控制、仅缩步、等幅随机、源回退、无越界恢复、不同物理步宽等对照。
